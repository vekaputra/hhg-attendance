# Raspberry Pi Relay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the repo into a VPS app (`server/`) that receives events over an HTTPS POST endpoint, and a Raspberry Pi
program (`relay/`) that talks EHome 4.0 UDP to the fingerprint device on the LAN, forwards events, and queues them on
`/data` when the VPS is unreachable.

**Architecture:** One Go module (`hhg-attendance`) with three packages:

- `internal/wire` holds the JSON message both sides exchange and the event hash.
- `server` (package main) is today's app, minus UDP, plus `POST /api/events` behind basic auth.
- `relay` (package main) answers REGISTER and KEEPALIVE itself, and POSTs every other message. ACS events go to a
  durable file queue when the POST fails, which is flushed hourly and after every successful live POST. Its logs are
  buffered in RAM and appended hourly to daily files.

**Tech Stack:** Go 1.27, standard library (plus the existing `modernc.org/sqlite` and `go-sql-driver/mysql` in the
server only), MySQL and SQLite, systemd and Raspberry Pi OS Lite (Trixie) on the Pi.

**Spec:** `docs/superpowers/specs/2026-10-23-pi-relay-design.md`

## Global Constraints

- **Two binaries:** `server/` builds the VPS app and `relay/` builds the Pi program. There is no mode switch in one
  binary.
- **The VPS accepts no UDP:** no EHome listener, no `7600/udp` in compose or the Dockerfile.
- **Relay UDP port:** `7600` by default.
- **Basic auth on both sides,** from env vars `RELAY_USER` and `RELAY_PASSWORD`. The server refuses every request when
  either is unset.
- **The relay requires an HTTPS URL** in `RELAY_URL` (it refuses anything not starting with `https://`).
- **Forwarding:** everything except `REGISTER` and `KEEPALIVE`. Only `ACS` gets ack-when-safe, queueing and retry;
  other commands are best-effort and never queued.
- **The queue** lives in `<data>/queue`, and `<data>` defaults to `/data`. Retry it hourly, and right after any
  successful live POST. Delete each event only after the VPS answered 200.
- **Logs:**
  - Buffer them in RAM and append them to `<data>/logs/YYYY-MM-DD.log` hourly and on SIGTERM or SIGINT.
  - Delete files older than 30 days.
  - Also write every line to stderr, which journald keeps in RAM under the overlay.
- **Event hash:** SHA-256, lowercase hex, of `DeviceID, SerialNo, Time, Major, Minor, EmployeeNo, CardNo` joined with
  `\x1f`, as the device sent them.
- **`received_at`** is the server's storage time. The dashboard shows "Last event received" from `MAX(received_at)`,
  with no warning.
- **Schema:** existing MySQL and SQLite databases gain `events.event_hash` in place, with no table recreation. Both
  schema files change together.
- **Images and builds:** the server image stays static distroless (`CGO_ENABLED=0`, `-tags timetzdata`). The relay
  also builds with `CGO_ENABLED=0`, for `GOARCH=arm GOARM=6` and `GOARCH=arm64`.

## Review Focus

- **The VPS is unreachable for days:** every queued event is delivered once, oldest first, and the queue ends empty
  (Task 6).
- **`/data` is missing, read-only or full:** enqueue fails, so the relay sends no ack and the device keeps the event
  (Task 6).
- **A power cut mid-write:** leftover `*.tmp` files and unreadable queue files are skipped and logged, never block the
  rest, and are never deleted (Task 6).
- **The device's ack gets lost, so it resends an event already stored:** the server keeps one event row and one tap
  (Task 4).
- **Something logs non-stop:** the RAM buffer flushes early at 4 MiB instead of growing without bound (Task 7).

### Task 4: `POST /api/events` on the server

**Files:**

  - `server/web.go`: mount the route outside `requireLogin` and outside `CrossOriginProtection`.
  - `server/main.go`: read `RELAY_USER` and `RELAY_PASSWORD`.

**Interfaces:**
- Consumes: `wire.Message` and `wire.EventHash` (Task 2), `Store.InsertEvent` with `Event.Hash` (Task 3), and the
  existing `Store.InsertTap`, `isTooLong` and `stampFmt`.
- Produces: package vars `relayUser` and `relayPassword` (strings). `ingestHandler(st *Store, loc *time.Location, now
  func() time.Time) http.Handler` is mounted at `POST /api/events`.

The behaviour, in this order:
1. **Auth:** if either credential is unset, or `r.BasicAuth()` doesn't match both (`subtle.ConstantTimeCompare`),
   answer **401**.
2. **Body:** read at most 64 KiB and decode one `wire.Message`. If it isn't valid JSON, or `Command` or `DeviceID` is
   empty, answer **400**.
3. **Non-ACS:** `slog.Info("relay message", command, deviceID, raw)`, then **200**.
4. **ACS:**
   - If `Hash != wire.EventHash(m)`, answer **400** (a relay bug, kept loud; the relay keeps the event).
   - Parse `Time` with `time.ParseInLocation(stampFmt, …, loc)`. If it fails, log a warning and answer **200**
     (dropped, as today).
   - `InsertEvent`, then, when `EmployeeNo != ""`, `InsertTap`, both with `received_at = now()`. If an error
     `isTooLong`, log it and answer **200**. Any other store error is a **500**.
   - Otherwise answer **200**.
5. **Every 200 has an empty body.** The relay treats only 200 as "stored, delete from the queue".

```go
// ehome.go — port of today's REGISTER/KEEPALIVE/403 logic (RegisterServer echo, resolveIPv4, localIPFor fallback,
// password never parsed or logged).
type ehome struct {
	allowed    []string        // RELAY_DEVICE_IDS
	registered map[string]bool // sender addresses that passed REGISTER
}
// handle returns the reply for the device and, for anything but REGISTER/KEEPALIVE from a registered sender,
// the message to forward (ACS fields filled and Hash set; other commands carry Raw). reply is the 200 ack.
func (e *ehome) handle(pkt []byte, from net.Addr) (reply []byte, msg *wire.Message)

// sender.go
type sender struct {
	url, user, password string
	client              *http.Client // Timeout 10s
	queueDir            string       // <data>/queue
	flushing            sync.Mutex   // TryLock: one flush at a time
}
func (s *sender) post(m wire.Message) error  // nil only on HTTP 200
func (s *sender) enqueue(m wire.Message) error // <queueDir>/<unixnano>-<hash>.json: write .tmp, fsync, rename, fsync dir
// deliver posts m; on failure it enqueues m. It returns nil if m was posted or queued. After a successful post it
// starts flush in a goroutine.
func (s *sender) deliver(m wire.Message) error
// flush posts queued files in name order and deletes each one that got a 200. On a network error or a 5xx it stops
// until next time. On another status, or a file it cannot read or decode, it logs, keeps the file and moves on.
// It ignores *.tmp files.
func (s *sender) flush()

// main.go
// serve reads packets from conn until it fails: REGISTER/KEEPALIVE get their reply;
// ACS gets the ack only if deliver returned nil; other commands get the ack and one best-effort post (never queued).
func serve(conn net.PacketConn, e *ehome, s *sender) error
```
